2D MMORPG Everia의 월드 채팅에 로컬 LLM(8B)을 결합하여 세 명의 AI NPC가 플레이어와 자연스럽게 대화하게 했다. LLM의 원문 출력을 5단계 검증 파이프라인으로 걸러 캐릭터 말투·맥락·정체성을 보장한다.Three AI NPCs in the 2D MMORPG Everia chat naturally with players in world chat, powered by a local 8B-parameter LLM. A 5-stage validation pipeline filters raw LLM output to guarantee character voice, context, and identity.2D MMORPG EveriaのワールドチャットにローカルLLM（8B）を結合し、3人のAI NPCがプレイヤーと自然に会話するシステムを設計・実装した。LLMの原文出力を5段階の検証パイプラインで濾過し、キャラクターの口調・文脈・アイデンティティを保証する。

전체 아키텍처Architecture Overview全体アーキテクチャ

게임 서버(Node.js + WebSocket)가 플레이어와 AI Seeker를 동일한 채팅 프로토콜로 연결한다. Seeker는 LLM에게 프롬프트를 보내고, 돌아온 원문을 screen() 파이프라인으로 검증한 뒤 통과한 응답만 월드 채팅으로 전송한다. 실패하면 최대 3회 재시도하고, 모두 실패하면 사전 정의된 대비 대사로 대체한다.The game server (Node.js + WebSocket) connects players and AI Seekers through the same chat protocol. Each Seeker sends prompts to the LLM, validates the response through a screen() pipeline, and only sends passing responses to world chat. On failure, it retries up to 3 times; if all fail, it falls back to pre-written lines.ゲームサーバー（Node.js + WebSocket）がプレイヤーとAI Seekerを同一チャットプロトコルで接続する。SeekerはLLMにプロンプトを送り、返答をscreen()パイプラインで検証し、合格した応答のみをワールドチャットに送信する。不合格時は最大3回リトライし、全て失敗すれば代替台詞で置き換える。

LLM은 서버에 직접 연결되지 않는다. Seeker가 WebSocket 클라이언트로서 서버에 접속하고, 내부적으로 LLM API를 호출한다. 서버 입장에서 Seeker는 일반 플레이어 클라이언트와 동일하다.The LLM is not directly connected to the server. Each Seeker connects as a WebSocket client and internally calls the LLM API. From the server's perspective, a Seeker is indistinguishable from a regular player.LLMはサーバーに直接接続されない。SeekerがWebSocketクライアントとしてサーバーに接続し、内部でLLM APIを呼び出す。サーバーから見ればSeekerは通常のプレイヤーと同一である。

세 캐릭터, 세 성격Three Characters, Three Voices3人のキャラクター

같은 LLM이 세 명의 서로 다른 캐릭터를 연기한다. 시스템 프롬프트와 후처리 파이프라인이 각 캐릭터의 말투·어조·응답 길이를 구분한다.A single LLM plays three distinct characters. System prompts and post-processing pipelines enforce each character's speech style, tone, and response length.同一のLLMが3人の異なるキャラクターを演じる。システムプロンプトと後処理パイプラインが各キャラクターの口調・トーン・応答長を区分する。

Astra — 존댓말 · 조용한 보호자Formal · Quiet Guardian敬語 · 静かな守護者

항상 존댓말. speechOk('polite')로 검증하며, 반말이 섞이면 거부·재생성. 응답 35자 이내.Always formal. Validated by speechOk('polite'); casual leaks are rejected. Max 35 chars.常に敬語。speechOk('polite')で検証、タメ口混入は拒否・再生成。応答35文字以内。

Echo — 반말 · 말수 적은 동료Casual · Terse Companionタメ口 · 寡黙な仲間

최대 15자의 짧은 반말. 존댓말은 toCasual()로 자동 변환, 변환 불가 시 거부. "~님" 호칭 금지.Max 15 chars of casual speech. Formal output auto-converted by toCasual(); "님" honorific banned.最大15文字の短いタメ口。敬語はtoCasual()で自動変換、変換不可なら拒否。敬称「님」禁止。

Vesper — 반말 · 밝고 장난스러운Casual · Bright & Playfulタメ口 · 明るくいたずら

에코보다 길게(25자). 같은 반말 검증이지만 장난·이모티콘 허용.Longer than Echo (25 chars). Same casual validation, but playful expressions and emoticons allowed.Echoより長く（25文字）。同じタメ口検証だが、いたずらっぽい表現と顔文字は許容。

screen() — 5단계 검증 파이프라인screen() — 5-Stage Validationscreen() — 5段階検証パイプライン

8B 모델은 지시를 무시하거나 존댓말과 반말을 섞거나 동료 이름을 뒤바꾸거나 프롬프트 지침을 수긍하는 응답을 낸다. screen()은 이런 결함을 런타임에 매 응답마다 잡아낸다.An 8B model ignores instructions, mixes speech styles, swaps names, or acknowledges prompts. screen() catches these defects at runtime on every response.8Bモデルは指示無視、口調混在、名前入替、プロンプト肯定をする。screen()はこれらをランタイムで毎応答検出する。

핵심 설계 결정: 재시도 힌트는 user 턴이 아닌 system 파라미터로 전달한다. user 턴에 넣으면 8B 모델이 "네, 말씀하신 대로…"식으로 수긍하는 메타 응답을 생성하기 때문이다. 이 분리만으로 메타 유출이 사실상 제거되었다.Key design decision: retry hints are passed via the system parameter, not the user turn. Placing hints in the user turn causes the 8B model to acknowledge developer feedback ("Yes, as you instructed…"). This separation alone virtually eliminated meta leaks.重要な設計判断：リトライヒントはuserターンではなくsystemパラメータで渡す。userターンに入れると8Bモデルが「はい、ご指示の通り…」とメタ応答を生成するためだ。この分離だけでメタ漏洩が事実上解消された。

해결한 실제 결함들Real Defects Fixed解決した実際の欠陥

  • 동료 이름 혼동Name confusion同僚名混同Astra가 "Echo의 이름은 아스트라입니다" 발화. hasNameContradiction() + 전용 힌트로 해결.Astra said "Echo's name is Astra." Fixed with hasNameContradiction() + targeted retry hints.Astraが「Echoの名前はアストラです」と発話。hasNameContradiction()＋専用ヒントで解決。
  • 쓸데없는 추임새Meaningless fillers無意味な相槌"네, 알겠습니다", "그렇군요" — 대비 대사를 자연스러운 문장으로 교체하고 필러 전용 응답 차단."Understood", "I see" — replaced fallbacks with natural lines and blocked filler-only responses.「はい」「そうですか」— 代替台詞を自然な文に差替え、フィラーのみの応答を遮断。
  • 합성봇에게 존칭Honorifics to bots合成ボットへ敬称Echo가 가짜 플레이어에게 "~님". 서버 /who에 ai 플래그 + isBotPattern() 휴리스틱으로 해결.Echo addressed fake players with honorifics. Added ai flag to /who + isBotPattern() heuristic.Echoが偽プレイヤーに敬称。/whoにaiフラグ＋isBotPattern()で解決。
  • 4차원의 벽 붕괴Fourth-wall breaking第四の壁崩壊"말씀하신 대로 '나'라고 표현하겠습니다". isMetaOrDeveloperSpeak() 18패턴 + system 파라미터 격리로 해결."I'll use 'I' as you instructed." Fixed with isMetaOrDeveloperSpeak() (18 patterns) + system-param isolation.「ご指示の通り『私』と表現します」。isMetaOrDeveloperSpeak()18パターン＋systemパラメータ分離で解決。

설계 판단과 한계Decisions & Limitations設計判断と限界

왜 로컬 LLM인가? — 개인 서버에서 운영되는 게임이다. API 과금 없이 24시간 구동하려면 로컬 추론이 유일한 선택이었다. 8B는 고급 추론에 약하지만 한 줄짜리 인게임 대사에는 충분하다. 부족한 품질은 후처리 파이프라인이 메운다.Why local LLM? — This game runs on a personal server. Local inference was the only option for 24/7 without API costs. 8B is weak at reasoning, but sufficient for one-line in-game dialogue. Quality gaps are covered by the post-processing pipeline.なぜローカルLLMか？ — 個人サーバー運営のゲームだ。API課金なしで24時間稼働にはローカル推論が唯一の選択肢。8Bは高度推論に弱いが一行の台詞には十分。品質不足は後処理パイプラインが補う。

아직 아닌 것 — 대화 기억은 세션 내에서만 유지된다. 장기 기억·감정 상태 추적은 미구현. 동시 대화 수가 늘면 LLM 추론 대기열이 길어지지만, 현재 규모(동접 10명 내외)에서는 문제 없다.Not yet — Memory only persists within a session. Long-term memory and emotion tracking are not implemented. High concurrency would create queue delays, but not at current scale (~10 users).未実現 — 会話記憶はセッション内のみ。長期記憶・感情追跡は未実装。同時会話数増加でキュー遅延が生じるが、現在規模（同接10名前後）では問題ない。
